# B站平台发布要求调研与适配说明

> 调研时间：2026-11。平台规则、接口字段与资质要求会持续调整，
> **最终以 B站官方文档与开发者后台的实时提示为准**。
> 本文把「已从官方文档确认」与「需在后台核实」的内容分开标注。

## 0. 先说清楚「tor 平台」

你提到的「B站 tor 平台」在官方口径里没有同名产品。按「把开源游戏发到 B站」
这个目标，实际有两条可行通道，本项目按**通道 A（小游戏）**做适配，
同时给出通道 B 的差异说明：

| | 通道 A：B站小游戏 | 通道 B：B站游戏开放平台 |
| --- | --- | --- |
| 入口 | https://miniapp.bilibili.com/small-game-doc | https://open.biligame.com |
| 形态 | H5/Canvas/WebGL，云端托管，免安装 | Android APK / PC 客户端，联运或买断 |
| 主体 | 个人开发者可注册（实名），企业更顺 | 基本要求企业主体 + 软著 + 版号 |
| 审核周期 | 首次创建审核约 3 天；资质 2~3 个工作日 | 5~7 个工作日初审起，视材料而定 |
| 适合本项目 | ✅ 纯 Canvas、无素材、包体 38 KB | ⚠️ 需 APK 打包 + 版号，个人很难过 |

**本项目的适配目标是通道 A**，通道 B 在文末给出差异清单。

## 1. 小游戏完整开发流程（官方）

1. 注册成为小游戏开发者（主体认证）
2. 设置域名白名单
3. 选择引擎（Cocos / Laya / Egret / Unity，或原生 Canvas）
4. 按小游戏目录结构组织工程（`game.js` + `game.json`）
5. 安装哔哩哔哩开发者工具
6. **接入启动埋点 `bl.launchSuccess()`，否则可能无法通过审核**
7. 本地调试
8. 上传成开发版
9. 后台扫码真机预览 → 提交审核 → 审核通过后**手动发布**

官方明确写了「掌握基本的 Canvas 绘图即可开发一款简单的小游戏」，
所以本项目不引入任何引擎，直接 Canvas 2D，包体最小、可控性最高。

## 2. 技术规格（已确认）

| 项目 | 要求 | 本项目情况 |
| --- | --- | --- |
| 包体总量 | 所有分包合计 ≤ 30 MB | 38 KB |
| 主包 | ≤ 4 MB | 38 KB，单包即可 |
| 单个分包 | ≤ 4 MB | 未使用分包 |
| 入口 | `game.js` + `game.json` | `npm run build:bilibili` 自动生成 |
| 渲染 | Canvas / WebGL | Canvas 2D |
| 资源托管 | 由平台云端托管，联网资源需合法域名 | 无外部资源，无需域名白名单 |
| 域名白名单 | 每类接口最多 20 个；不可配置 `.bilibili.com` | 不涉及网络请求 |
| 引擎版本 | Cocos 2.2+/3.3+、Laya 2.1+/3.x、Egret、Unity 2021.3 | 不使用 |

说明：部分引擎方案要求资源放 CDN（Unity 导出必须），
本项目所有画面都是代码实时绘制，**没有图片/音频文件**，因此规避了 CDN 与域名配置。

## 3. 必接能力（审核会查）

| 能力 | 说明 | 本项目状态 |
| --- | --- | --- |
| 启动成功埋点 | 首页渲染成功后调用 `bl.launchSuccess()` | ✅ `platform/bilibili/bootstrap.js` 在首帧后调用一次 |
| 侧边栏复访 | 引导用户从 B站侧边栏再次进入 | ⚠️ 需按后台最新 API 补齐 |
| 桌面快捷方式 | 引导添加桌面图标 | ⚠️ 需按后台最新 API 补齐 |
| 提审包洁净 | 不得含 Toast、测试入口、调试日志 | ✅ 构建产物无调试入口 |
| 隐私合规 | 采集信息需隐私政策明示 | ✅ 本项目不采集任何用户信息 |

⚠️ 后两项（侧边栏复访、桌面快捷方式）的 API 名称与调用时机在官方文档中随版本变化，
我没有在官方文档中确认到稳定的函数签名，因此**没有臆造调用**，只保留了接入位置
（见 `bootstrap.js` 第 7 节注释）。上线前请在开发者后台按当期文档补齐，并真机验证。

## 4. 资质、备案与审核流程

### 4.1 材料

| 材料 | 说明 | 本项目相关 |
| --- | --- | --- |
| 主体认证 | 个人实名或企业营业执照 | 你提供 |
| 小游戏备案 | 平台侧备案，需主体信息 | 你提供 |
| ICP 备案 | 域名/主体备案；已有其他平台备案号可按要求提交 | 你提供 |
| 软件著作权 | 建议登记（审核加分项，纠纷时是证据） | 建议用本仓库申请 |
| 版号（ISBN） | 涉及内购/付费下载时需要 | 本项目免费无内购，通常走非商业/测试通道 |
| 隐私政策 | 若有信息采集 | 本项目无采集，可提供一页说明 |

已确认的时效信息：资质审核约 2~3 个工作日；首次创建审核约 3 天；
备案走主管部门审核，周期较长，且需完成短信核验。

### 4.2 审核关注点（内容规范）

- **版权与原创性**：不得山寨抄袭、不得使用未授权素材。2048 玩法本身可复刻，
  但名称、图标、美术必须自有 —— 本项目已全部自绘，且名称加了「像素版」区分。
- **内容安全**：无暴力、低俗、赌博、诱导消费内容。益智类天然低风险。
- **未成年人保护**：无内购、无社交、无广告，风险最低。
- **概率公示**：涉及随机抽取/抽卡才需要；本项目的随机仅影响方块生成，不涉及付费。
- **不得含外部引流**：本项目无外链、无二维码。

### 4.3 提审注意

- 提审包必须是可正式发布的版本，调试代码要清理
- 需补齐名称、图标、介绍、截图、测试说明
- 审核通过 ≠ 上线，要在后台执行**发布**动作
- 名称需与软著/版号一致（若已登记）

## 5. 本项目如何映射到平台

```
npm run build:bilibili
      ↓
dist/bilibili/
├── game.js              ← 入口，按顺序 require 各模块
├── game.json            ← 竖屏、无状态栏
├── src/                 ← 与浏览器版同一份代码
│   ├── core/game.js
│   ├── core/storage.js
│   ├── render/renderer.js
│   └── app.js
└── platform/bootstrap.js ← 平台壳：画布、尺寸、存储、触摸、launchSuccess
```

适配层只做 7 件事（对应 `bootstrap.js` 注释 1~7）：
存储适配、取画布、取屏幕尺寸、触摸绑定、尺寸变化、前后台保存、启动埋点。

浏览器与小游戏共用 `src/` 全部游戏逻辑，因此**不存在两套代码走偏**的问题。

## 6. 通道 B（APK / PC 联运）差异

若要走 `open.biligame.com` 的联运：

| 差异点 | 说明 |
| --- | --- |
| 打包 | 需要 WebView/Cordova/Capacitor 或原生壳把 `index.html` 包成 APK |
| 资质 | 企业主体 + 软著 + 版号（付费/内购必须） |
| SDK | 需接入 B站登录、支付、防沉迷 SDK |
| 审核 | 更严：机型兼容、崩溃率、安装包体积、隐私弹窗 |
| 结论 | 个人开发者不建议走这条；先用小游戏验证留存，再考虑联运 |

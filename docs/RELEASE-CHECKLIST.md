- [ ] 图标（512×512 PNG，建议用像素风方块组合，自行设计）
- [ ] 一句话简介 + 详细介绍（可直接取 README 首段）
- [ ] 截图 3~5 张（可用 `docs/screenshots/` 里的两张作为起点，按平台尺寸要求重截）

- [ ] 小游戏备案 + ICP 备案（按后台指引，需短信核验）
- [ ] 软著证书（如有）
- [ ] 版号（仅内购/付费需要；本项目免费无内购，通常不需要）

## F. 提交与上线步骤

1. **构建**
   ```bash
   npm test
   npm run build:bilibili
   ```
2. **导入工程**：打开哔哩哔哩开发者工具 → 新建项目 → 选择 `dist/bilibili` → 填 AppID
3. **本地调试**：确认无报错，检查启动埋点是否触发（后台「启动成功」应有数据）
4. **上传开发版**：填写版本号（如 `1.0.0`）与更新说明
5. **真机预览**：用已加入预览名单的 B站账号扫码，逐项过一遍第 A、C 节的真机项
6. **补齐材料**：名称、图标、介绍、截图、测试说明、资质（第 E 节）
7. **提交审核**：从已验证的开发版发起，不要重新打包
8. **等待审核**：资质约 2~3 个工作日，首次创建审核约 3 天；被驳回按原因整改后重提
9. **发布上线**：审核通过后必须在后台点「发布」，否则线上仍是旧版本/不可见
10. **线上复核**：从真实入口（游戏中心/分享链接）进入，确认版本、页面、存档都正常

## 常见被拒原因（对照自查）

| 原因 | 本项目的风险 | 处理 |
| --- | --- | --- |
| 未接启动埋点 | 已接，仍需真机确认上报成功 | 开发者工具看网络/后台看数据 |
| 提审包含调试代码 | 构建产物无调试入口 | 每次提审前重新构建 |
| 素材未授权 | 零外部素材 | 保持 |
| 与已有产品同质化 | 「2048」品类高度同质 | 用像素风差异化，名称/图标自有，介绍里强调原创实现 |
| 名称与资质不一致 | 若已登记软著 | 保持一致 |
| 审核通过未发布 | 常见疏漏 | 第 9 步 |

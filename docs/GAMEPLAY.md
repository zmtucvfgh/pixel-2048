# 玩法、关卡与功能梳理

本文档梳理 2048 类游戏的功能面，并说明本项目的实现边界与参数，
既是设计说明，也是后续迭代的对照表。

## 1. 核心玩法

| 项目 | 规则 | 本项目实现 |
| --- | --- | --- |
| 棋盘 | 4×4 网格 | 支持任意 `size`（默认 4，代码可配 5×5） |
| 初始局面 | 随机两个方块 | 开局生成 2 个 |
| 生成概率 | 90% 为 2，10% 为 4 | 一致 |
| 移动 | 上/下/左/右，所有方块向该方向靠拢 | 键盘、WASD、滑动、鼠标拖拽 |
| 合并 | 相邻同值合并为两倍值，每次移动每个方块最多参与一次合并 | 一致，且做了「合并产物本回合不再合并」的校验 |
| 得分 | 每次合并获得合并后的数值 | 一致 |
| 胜利 | 出现 2048 | 出现后弹层，可选择继续挑战更大方块 |
| 失败 | 棋盘填满且四邻无可合并 | 一致，弹层显示本局得分 |
| 随机性 | 位置与数值随机 | 可注入 `rng`，测试时使用确定性随机 |

合并顺序细节（易错点，已单测覆盖）：

```
[2, 2, 2, 2]  向左 → [4, 4]        得分 8（不是 8 + 一个 4）
[2, 2, 4, 0]  向左 → [4, 4]        得分 4（新生成的 4 不再与旁边 4 合并）
[0, 4, 0, 4]  向右 → [0, 0, 0, 8]  得分 8
```

## 2. 关卡设计

2048 属于**无尽模式**，没有传统关卡概念，难度曲线由数值增长自然形成：

- 0–512：热身区，几乎不会失败
- 1024–2048：需要开始规划角块与「蛇形」排列
- 4096 以上：需要严格的角落策略，容错极低

本项目额外提供：

- **撤销**：默认保留最近 20 步快照（可配置 `historyLimit`），降低误操作成本
- **自动存档**：随时关闭页面都能从原局面继续

如需做「关卡制」变体，可在 `src/core/game.js` 上叠加：
限定步数、限定目标方块、障碍格、多棋盘接力等，都属于扩展方向，当前未实现。

## 3. 资源清单

本项目刻意做到**零外部素材**，既规避版权风险，也保证包体极小（约 38 KB）：

| 资源类型 | 来源 | 说明 |
| --- | --- | --- |
| 方块、棋盘、按钮 | Canvas 2D 代码绘制 | 颜色表见 `TILE_COLORS` |
| 高光/阴影 | 代码绘制的像素风亮条 | 营造方块立体感 |
| 音效 | WebAudio 振荡器合成 | 移动、合并、撤销、胜利、失败共 5 类 |
| 字体 | 系统字体栈 | 不打包字体文件 |
| 图片/音频文件 | 无 | 仓库中不存在二进制素材 |

因此不存在「素材授权链」问题，也不会触发平台对未授权素材的审核项。

## 4. UI 与交互

界面全部绘制在同一张 Canvas 上（这样同一份代码能跑在只提供 Canvas 的小游戏容器里）。

布局（自上而下）：

1. 标题区：`2048` + `像素版` 副标题，右侧两个数值框（分数 / 最高）
2. 棋盘：4×4 方格，圆角 8px，格子间距随尺寸自适应
3. 工具栏：`新游戏` / `撤销`（无步可退时置灰）/ `音效 开|关`
4. 底部提示：操作方式与合并规则
5. 弹层：胜利（继续挑战 / 再来一局）、失败（再来一局）

交互细节：

- **按钮**：按下时下移 1px 并变亮，抬手时命中才触发（与触屏习惯一致）
- **滑动**：位移 ≥ 22px 判定为滑动；小于 12px 视为点击；中途超过 12px 会取消按钮按压
- **动画**：滑动 150ms 缓出；合并方块有 8% 的弹跳；新方块从 25% 缩放出现；被吞并的方块后 45% 时间淡出
- **自适应**：内容最大宽度 560px，窄屏自动缩小标题与字号，底部提示会按宽度自动降字号避免裁切
- **无障碍**：Canvas 带 `aria-label`，分数变化通过 `aria-live` 区域朗读

## 5. 操作方式

| 输入 | 行为 |
| --- | --- |
| `↑ ↓ ← →` / `W A S D` | 移动 |
| 触屏滑动 / 鼠标拖拽 | 移动 |
| `R` | 新游戏 |
| `Z` / `U` | 撤销 |
| `M` | 音效开关 |

小游戏端复用同一套逻辑，仅把 Canvas 触摸事件换成平台 `bl.onTouchStart` 等接口。

## 6. 存档与数据

存储键统一前缀 `pixel2048.v1.`：

| 键 | 内容 |
| --- | --- |
| `state` | `{size, grid, score, won, over, keepPlaying}`，每次移动后写入 |
| `best` | 历史最高分 |
| `muted` | 音效开关 |

浏览器用 `localStorage`；小游戏端通过 `Pixel2048Storage.useAdapter()` 注入
`bl.getStorageSync / bl.setStorageSync`，业务代码无需改动。

存档时机：每次有效移动后、点击按钮后、切后台/关闭页面时（`pagehide`、`visibilitychange`、`bl.onHide`）。
恢复策略：启动时若有存档则直接续玩；若恢复后发现已无可行步，直接置为结束态。

## 7. 代码结构

```
index.html                 浏览器入口（仅 canvas + 脚本引用）
src/core/game.js           规则引擎：移动、合并、计分、胜负、序列化（无 DOM）
src/core/storage.js        存档抽象：localStorage / 平台存储适配
src/render/renderer.js     Canvas 渲染 + 命中测试 + 动画
src/app.js                 应用层：音效、按钮动作、存档联动（平台无关）
src/main.js                浏览器壳：指针/键盘/尺寸
platform/bilibili/         B站小游戏壳：画布、触摸、启动埋点
```

分层原则：**规则不依赖渲染，渲染不依赖 DOM API 之外的平台能力**，
因此新增平台（微信小游戏、TapTap、Steam via Electron 等）只需再加一个壳。
